# Agent operation catalog

Audit date: 2026-11-24. This catalog groups actions a person can name; the exact design tool schemas are in `cli/tools.json` and the live MCP `tools/list`. The desktop editor stores projects and history in IndexedDB; the CLI opens an exported project file in the same editor and writes it back. The editor also has account and cloud sync. IDs in a saved project are used by the design tools, but import and recreation do not promise to preserve every ID.

| Operation and human path | Machine path and input → output | Side effects and limitations |
| --- | --- | --- |
| Inspect templates; choose one on the start screen | `osg templates --json` → template metadata | Reads the packaged templates. |
| Create or import a project from the start screen | `osg init`, `new`, `fill`, `import`, `design` → configuration, project or downloaded assets | Writes local files; import and design can contact external services. Design can use a paid provider. |
| Open a project, inspect boards, layers and locales | `osg status`, `osg list`, `osg get <artboard-id>` inspect an exported file; `osg call list_artboards`, `get_artboard`, `list_locales` use editor tools | File inspection is read-only and reports the stored base document, not the desktop app's project database or a localized view. `call` does not save to the file unless `--save` is used. |
| Edit, add, remove, reorder or group boards and elements | `osg edit --tool ...` or `osg call <tool> ... --save`; MCP design tools → results and IDs | Writes project state. The CLI requires `--yes` and MCP requires `confirmed: true` for `delete_artboard`, `delete_element`, `delete_asset`, `remove_locales`, `reset_locale_overrides` and `apply_template`; CLI checks an entire batch before starting. `edit` saves by default and can save successful earlier calls after a later call fails. No general dry run or idempotency key. |
| Manage languages and translated copy in the editor | `osg localize` and locale design tools → locale state or translation results | Adding, editing or translating writes project data; translation can send text to a provider. `--dry-run` only supports CSV import without other writes. CSV export writes a file. |
| Export screenshots and preview video | `osg render`, `osg video`, export tools → files | Writes output files; rendering can fetch uncached assets and fonts. |
| Review a store set | `osg verify <dir> --store appstore\|play --json`; `osg manifest` → verdicts or manifest | Verify reads exported files; manifest writes a file. Store rules cannot assess visual quality or guarantee acceptance. |
| Capture a device in the Capture view | Desktop MCP `list_capture_devices`, `capture_screenshot` → device list or image placement | Requires the desktop environment and device tooling. OS permissions and device authorization remain human actions. Physical device behavior requires device testing. |
| Upload screenshots to a store | `osg upload --store ... --dry-run`, then `osg upload` → plan or upload result | Dry run still reads credentials, contacts the store and renders; it does not upload images. A real upload changes store data. Replacement with `--replace` requires `--yes`. Requires explicit authorization. |
| Manage local cache | `osg cache info`, `warm`, `seed`, `prune` → cache information or result | Warm may download; seed writes; prune deletes and requires `--yes`. `prune --dry-run` previews removal. |
| Select editor and open Studio | `osg editor status\|use\|reset`, `osg studio` | `use` and `reset` change CLI configuration; Studio opens an editor. |
| Diagnose environment | `osg doctor --json` | Starts a browser and makes a temporary probe database; `--install-browser` downloads and installs a browser. It is not a strictly side-effect-free status command. |
| Batch the pipeline | `osg all` | Can write files and invoke model services. Review the requested flags and outputs first. |
| Expose or register MCP | `osg mcp --stdio` or `--http`; `osg install` | MCP serves tools with read and write capabilities. Install edits agent configuration. HTTP binds loopback and requires a token. |
| Call a running desktop app | `osg desktop-call <tool> --port <port> --args '<json>' --agent-json` | Connects to `127.0.0.1` with a bearer token from the environment. It uses the app's existing tool permissions and operations; the token is never passed as a command argument. A tool's own side effects and confirmations still apply. |
| Inspect a website draft for a project | Desktop MCP `get_website_draft` → draft metadata and content | Reads the current Website view's copy when open and the stored draft otherwise; does not return AI chat or authentication. A loading draft is reported as loading, not missing. Only the app's own agents may read it. |
| Create a website draft | Desktop MCP `create_website_draft` → preview or local draft | Uses the open project's captions, colours and languages. Defaults to preview; applying requires confirmation and an unchanged project. Privacy answers remain unanswered; this does not publish. |
| Edit website copy and presentation | Desktop MCP `update_website_draft` → preview or stored update | Uses the Website editor's validation and storage. Defaults to preview; applying requires confirmation and the expected values from the unchanged preview. Supports text, features, FAQs, colours, display options, languages, privacy answers and addresses. Other windows must not edit the same site concurrently. |
| Translate a website draft | Desktop MCP `translate_website_draft`; UI Translate | Preview missing languages before authorizing text sent to configured translation providers. Execution requires confirmation and the unchanged preview. Provider selection may change; inspect incomplete languages and errors afterward. |
| Publish a website | Desktop MCP `publish_website_draft`; UI Publish | Defaults to an offline preview. Publishing requires the user's authorization, a matching preview and a connected GitHub account. The tool checks readiness and captures the open project through the Website renderer. A timeout or error can leave remote work running; check GitHub before retrying. |
| Track and stop tracking Growth keywords | Desktop MCP `get_keyword_tracking`, `track_store_keywords` and `untrack_store_keyword`; UI Keywords view | Changes the local tracked list through the same service as the UI. A scheduled check may later search Apple. The app's own agents may write; external MCP clients retain their existing read-only access. Changes default to preview; applying requires confirmation. Removal retains historical ranks and checks the previewed version. |
| Mark a store review as needing no reply or return it to the inbox | Desktop MCP `set_store_review_done`; UI Reviews view | Changes the local review mark through the UI's transactional service; never sends a reply. Preview and confirmation are required, and a changed mark is rejected. |
| Prepare a reply to a review | Desktop MCP `prepare_store_review_reply`; UI Reviews view | Saves a local draft after preview and confirmation. The Reviews view offers the draft for a person to review and send; preparing never sends it to a store. |
| Send a prepared review reply | Desktop MCP `send_prepared_store_review_reply`; UI Reviews view | Requires the user's authorization and a matching preview. Rechecks the review at the store; a missing or changed review prevents sending. The store can change after the check. After an uncertain result, check the store before retrying. |
| Manage reusable review reply templates | Desktop MCP `list_review_reply_templates`, `change_review_reply_template`; UI Growth → Replies | Reads and changes the shared local templates. Changes default to preview and require confirmation and the unchanged plan. Deleting a template does not change reviews or send replies. Avoid editing the same templates in another window concurrently. |
| Tag a store review | Desktop MCP `list_review_tags`, `set_store_review_tag`; UI Growth → Reviews | Reads existing local tags and adds or removes one tag on a local review mark. Defaults to preview; applying requires confirmation and the unchanged review mark and tag. Does not contact a store. |
| Manage review tags | Desktop MCP `change_review_tag`; UI Growth → Replies | Creates, renames, recolours or deletes a shared local tag. Deletion previews how many review marks will lose it and applies the tag and mark changes in one transaction. Defaults to preview and requires confirmation. |
| Prepare edits to store listing text | Desktop MCP `get_store_listing_drafts`, `update_store_listing_drafts`; UI Store page | Reads and updates local drafts through the UI's draft service. Changes default to preview, require confirmation and a matching revision to save, and are not sent to Apple or Google. Other windows must not edit the same draft concurrently. |
| Apply listing drafts to a store | Desktop MCP `apply_store_listing_drafts`; UI Store page | Defaults to a local preview. Sending requires the user's authorization, confirmation and an unchanged plan. The desktop checks the current store page before writing; provider APIs cannot prevent another change after that check. Partial or uncertain results require a refresh before retrying. |
| Inspect project sync state | Desktop MCP `get_project_sync_status` → local status | Reports local account/cloud state without tokens, share links, room keys or network requests. It is not a remote freshness check. Only the app's own agents may read it. |
| Request sync to the existing account copy | Desktop MCP `request_project_account_sync` → preview or asynchronous request | Uses the same syncer as the account chip and may send project data to the connected provider. Requires the user's authorization, confirmation and the unchanged preview. Check status for the eventual outcome; a request is not a completed save. It cannot turn on a stopped project. |
| Stop automatic updates to the open project's own storage | Desktop MCP `pause_project_account_sync` → preview or local setting change | Uses the same per-project setting and syncer notification as the conflict dialog. Requires a connected matching account and a confirmed preview; no remote copy is removed. A request already in flight may finish. |
| Resume automatic updates to an existing account copy | Desktop MCP `resume_project_account_sync` → preview or local setting change | Requires the user's authorization and a confirmed, unchanged preview. A previous manual save and a known remote revision are required; a later automatic sync may send project data and still stops on a detected conflict. |
| Change link sharing for a saved cloud copy | Desktop MCP `set_cloud_project_sharing` → preview or conditional update | Requires the user's authorization and a matching preview. Enabling shares the last saved cloud copy; disabling revokes links. It refuses during live editing and does not return the link. The server must have the conditional sharing endpoint; the tool refuses rather than falling back to an unconditional write. |
| Start or leave live editing | Desktop MCP `start_project_collaboration`, `stop_project_collaboration`; UI Edit together | Starting requires the user's authorization and an already shared cloud copy. It can create the first local room key. Peers can change the local project. Leaving does not revoke the invite. Neither action returns the room key or invite link. |
| Other Growth and account settings | GUI and the documented integrations in `docs/ACCOUNT-SYNC.md`, `docs/WEBSITE.md`, `docs/GROWTH.md` | Coverage outside the operations listed here has not been established. External writes require authorization. |
| Inspect versions, AI runs or undo in the editor; review CLI execution results | GUI project history; MCP `list_project_versions` reads saved version metadata; `list_ai_runs` reads AI run metadata; `osg history` reads the CLI's local command-result log | Project versions are snapshots. AI run metadata excludes prompts, responses, images and error messages. The CLI log contains command, time and exit category, not project content or arguments. None of these is a complete record of all GUI and MCP actions. |
| Restore a project version | Desktop MCP `restore_project_version`; UI History → Versions | Preview first, then confirm the unchanged plan. A safety version is required before replacing the open canvas. The change enters ordinary undo history and may be sent to live-editing peers. The tool reports local persistence as pending. |
| Grant OS permissions, authorize a device, sign in, solve CAPTCHA, judge visual quality | Human in the relevant OS, account or editor screen | Human action is required. Do not claim a headless check verified visual quality. |

## Audit and target

Current strict level for the whole app: **L0 with partial L1–L3 capabilities**. Non-streaming CLI commands offer a versioned outer JSON envelope, but inner result shapes vary. Desktop operations are available through `desktop-call`; CLI file inspection and execution history do not cover all desktop state or GUI/MCP history. Some Growth, account and sharing workflows still lack equivalent machine paths, and conditional cloud sharing also needs a server deployment. Target: **L2**, reached only after the principal operations and their read paths are covered and tested. L3 remains a later step; the existing export verifier alone does not establish it.

The GUI and the CLI both use the editor bridge and design tools; some state and orchestration remain in the layout. Project versions exist in Dexie, but they are not a CLI execution history. Unit tests and browser tests exist; see `docs/CLI.md` and the repository test scripts. Stable IDs across all import and migration paths, real devices, live stores and external integrations are not verified by this audit.

Known gaps include the first save to an account or cloud copy, sharing or distributing a collaboration invitation, and Growth settings and workflows not listed above. These are not all inherently human-only; they need machine paths and tests before app-wide L2 can be claimed. The existing share change also requires the conditional endpoint to be deployed separately.
